# C 笔记 10

2026-11-19

## 概念

signed 表示这个类型带正负号, 能存负数.
unsigned 表示不带正负号, 只能存 0 和正数.
这两个关键字只能修饰字符型和整型, 浮点型没有无符号这一说.

## int 默认就是带符号的

int 等于 signed int.
因为是默认情况, signed 一般省掉不写, 写了也不算错.
想不带符号就必须写 unsigned int, 不写就是默认的有符号.

## 无符号能装的最大值更大

同样长度, 无符号把原来留给负号的那一半也拿来放正数, 所以最大值翻倍.
short 的范围是 -32768 到 32767.
unsigned short 的范围是 0 到 65535.
int 的范围是 -2147483648 到 2147483647.
unsigned int 的范围是 0 到 4294967295.
具体数值可以查 limits.h, 那是标准库给的一份范围清单.

## 范围是个圈

每个整型的范围都是首尾相接的一个圈, 不是一条从负到正的直线.
short 的圈: 32765 → 32766 → 32767 → -32768 → -32767 → ... → -1 → 0 → 1 → ...
32767 再加 1 不会变成 32768, 而是落到圈的另一头, 那一格是 -32768.
圈上 -32768 和 32767 挨着, 所以落到的不是 -32767.
负数这边多一个, 因为 0 占在正数这边: 0 到 32767 是 32768 格, -32768 到 -1 也是 32768 格.
反方向也一样: -32768 再减 1 打 32767.
无符号的圈: 255 再加 1 打 0, 0 再减 1 打 255.

## 同一份数据两种看法

```
int i = -1;
printf("%d\n", i);   打出来 -1
printf("%u\n", i);   打出来 4294967295
```

数没变, 变的是我按有符号读还是按无符号读.
%d 按有符号解释, %u 按无符号解释.

## 真的绕回去

```
unsigned int ui = 4294967295;
printf("%u\n", ui + 1);   打出来 0
```

ui 自己就是无符号, 加完还是无符号, 到顶了再往上就回到 0.

## short 要装回去才绕

```
short s = 32767;
printf("%d\n", s + 1);   打出来 32768
s = s + 1;
printf("%d\n", s);       打出来 -32768
```

第一句没绕, 因为 short 参与计算时会先变成 int, 32768 装得下.
第二句绕了, 因为算完的 32768 要装回 short, 装不下.
所以"绕过没绕过"要看他最后装进哪个类型.

## char 的符号性不确定

char 到底是有符号还是无符号, 标准没规定, 由编译器决定.
它可能等于 signed char, 也可能等于 unsigned char.
我这台机器上 char 是有符号的:

```
char c = 200;          用 %d 打出来 -56
unsigned char uc = 200; 用 %u 打出来 200
```

所以只要存的数可能超过 127, 就要把 signed 或 unsigned 写清楚, 别只写 char.

## char 也算整型家族

char 存的是一个字符, 存进去的是它的 ASCII 值.
ASCII 值是整数, 所以字符型属于整型家族.
这也是为什么 signed 和 unsigned 能修饰 char.

## 和 Python 比

Python 的整数没有无符号这一说, 负数就是负数, 也没有"最大值翻倍".
Python 的 int 长度不限, 不会绕回去.
C 要我选: 会不会有负数, 数最大到多少, 两个都选错就出问题.

## 结论

signed 管正负, unsigned 只管非负, 同样长度下无符号的最大值翻倍.
每种整型都有自己的圈, 超出范围不报错, 在圈上绕回去.
char 的符号性不固定, 要用就自己写清楚.
